# 통합 피드백 게시판

부산대 AI융합교육원 5개 시스템의 피드백을 한 곳에 모아 보는 사이트.

## 대상 사이트
| 코드 | 이름 |
|---|---|
| codeplace | 코드플레이스 |
| aipms | AIPMS |
| aicms | AICMS |
| aicap | AI역량지원시스템 |
| srvadm | pickle (서버관리) |

## 기술
- 백엔드: Spring Boot 3.x / JDK 21 / JPA / Spring Security / PostgreSQL
- 프론트: React (Vite)

## 폴더 구조
```
backend/    스프링부트 (서버)
frontend/   React (화면)
docs/       기획 문서, 화면 그림
```

## 처음 받는 사람

```bash
git clone https://github.com/PNUFeedbackBoard/feedback-board.git
```

설치해야 할 것: JDK 21, IntelliJ, Node.js(LTS), VS Code
자세한 건 `docs/setup-guide.md`

빠른 실행은 저장소 루트에서 다음 명령을 사용합니다.

```powershell

```

상세한 설치, 실행, 검사 방법은 [개발환경 설정 가이드](docs/setup-guide.md)를 참고하세요.

## 주요 기능

### 사용자 기능

로그인 화면에서 비회원 또는 회원(구글 로그인)을 선택할 수 있습니다.

#### 비회원

비회원으로 선택 시 문의에 대한 답변과 진행상태, 이전에 작성한 내용 확인이 어렵습니다.

- 피드백 작성
- 피드백 유형 선택
  - 기능 제안
  - 오류 신고
  - 기타 의견
- 제목과 내용 작성
- 피드백 제출

#### 회원

- 구글 로그인
- 피드백 작성
- 피드백 유형 선택
  - 기능 제안
  - 오류 신고
  - 기타 의견
- 제목과 내용 작성
- 피드백 제출
- 내가 작성한 문의에서 작성한 내용 확인
- 개발자의 답변 확인
- 피드백 진행 상태 확인

### 관리자 기능

- 전체 피드백 조회
- 피드백 필터링(사이트별 / 오래된순 / 최신순 / 중요도순 / 진행상태별 / 유형별 / 상태별 / 기간별)
- 피드백 상태 변경
  - 접수
  - 처리 중
  - 처리 완료
  - 반영 불가
- 각 상태마다 다른 색상의 상태 배지 표시
- 개발자 답변 작성
- 피드백 통계 확인(전체 사이트 피드백 개수, 전체 사이트 상태별 피드백 개수, 특정 카테고리별 피드백 개수, 피드백 작성 일시, 사용자 수, 평균 처리 소요 시간, 기간별 피드백 추이)

## 비회원 사용자 여정

비회원은 로그인 없이 피드백을 작성할 수 있습니다.

```text
사이트 링크 접속
    ↓
비회원 선택
    ↓
비회원 경고문 확인
    ↓
피드백 작성
    ↓
제목과 내용 입력
    ↓
피드백 유형 선택
    ↓
제출
```

비회원으로 제출한 문의는 이후 답변, 진행 상태, 이전 작성 내용 확인이 어렵습니다.

## 회원 사용자 여정

### 피드백 작성

```text
사이트 링크 접속
    ↓
회원 로그인 선택
    ↓
구글 로그인
    ↓
'작성하기' 선택
    ↓
피드백 작성
    ↓
제목과 내용 입력
    ↓
피드백 유형 선택
    ↓
제출
```

### 피드백 진행 상태 확인

```text
사이트 링크 접속
    ↓
구글 로그인
    ↓
'내가 작성한 문의' 선택
    ↓
작성한 내용 확인
    ↓
개발자의 답변 확인
    ↓
피드백 진행 상태 확인
```

## 피드백 유형

| 유형 | 설명 |
|---|---|
| 기능 제안 | 기존 서비스에 추가되었으면 하는 기능 |
| 오류 신고 | 서비스 이용 중 발생한 오류나 문제 |
| 기타 의견 | 기능 제안이나 오류 신고에 포함되지 않는 의견 |

## 피드백 처리 상태

| 상태 | 설명 | 배지 색상 |
|---|---|---|
| 접수 | 사용자가 피드백을 제출한 상태 | 파란색 |
| 처리 중 | 피드백에 대한 수정이나 조치를 진행 중인 상태 | 주황색 |
| 처리 완료 | 피드백에 대한 조치가 완료된 상태 | 초록색 |
| 반영 불가 | 현재 반영하기 어려운 상태 | 회색 또는 빨간색 |

## 관리자 피드백 처리 흐름

```text
관리자 로그인
    ↓
피드백 관리 화면 접속
    ↓
사이트별·정렬 기준·중요도·진행 상태·유형·기간별 필터링
    ↓
피드백 내용 확인
    ↓
처리 상태 변경
    ↓
필요한 경우 개발자 답변 작성
    ↓
처리 완료 또는 반영 불가 처리
```

## 브랜치 규칙

```
main      배포된 것만. 직접 push 금지
develop   평소 작업이 모이는 곳
feature/  각자 작업 브랜치
```

### 흐름
```
feature/내작업  ->  develop  ->  main
                   PR         배포할 때만
```

### 작업할 때
```bash
git checkout develop
git pull
git checkout -b feature/feedback-write   # 본인 작업 이름
# ... 작업 ...
git add .
git commit -m "feat: 피드백 작성 화면"
git push -u origin feature/feedback-write
```
그다음 GitHub에서 PR 올린다. **받는 쪽(base)을 `develop`으로** 둔다.
2명이 확인하면 합친다.

### 브랜치 이름
- `feature/영문-소문자-하이픈` 예: `feature/admin-page`
- 한글, 띄어쓰기 안 씁니다

### 커밋 메시지
```
feat: 새 기능
fix: 버그 수정
docs: 문서
chore: 설정, 잡일
```

# 통합 피드백 게시판 기획안

부산대학교 AI융합교육원 소속 5개 시스템의 버그 신고·피드백을 한 곳에 모아,
사용자는 쉽게 신고하고 개발자와 실장님은 진행 상황을 한눈에 보는 서비스.

- 문서 버전: v1.0 (2026-09-10)
- 상태: 결정 완료 · 개발 착수 가능
- 관련 문서: [README](../README.md), [개발환경 설정 가이드](setup-guide.md)

---

## 1. 배경과 목표

교육원의 5개 시스템은 각각 따로 피드백을 받고 있어서, 어떤 문제가 얼마나 쌓여 있고
무엇이 처리됐는지 한 번에 보기 어렵다. 이 서비스는 두 가지를 동시에 푼다.

| 대상 | 문제 | 이 서비스가 주는 것 |
|---|---|---|
| 실사용자 | 어디에 신고해야 할지 모르고, 신고해도 처리됐는지 모름 | 사이트별 링크 하나로 신고, 답변과 진행 상태 확인 |
| 개발자 | 피드백이 메신저·구두·메일로 흩어짐 | 프로젝트별 칸반 보드와 답변 대기열 |
| 실장님 | 5개 프로젝트의 전체 상황 파악 불가 | 전체 현황 대시보드 한 페이지 |

**설계의 핵심 갈등과 해법**: 실장님은 "전체를 모아 보기"를, 개발자는 "프로젝트별로 나눠 보기"를
원한다. 두 요구가 상충하므로 **페이지를 목적별로 분리**한다.
홈 = 전체 대시보드(실장님용), 프로젝트 상세 = 프로젝트별 작업 화면(개발자용).

## 2. 대상 사이트 (프로젝트)

| 코드 | 이름 |
|---|---|
| `codeplace` | 코드플레이스 |
| `aipms` | AIPMS |
| `aicms` | AICMS |
| `aicap` | AI역량지원시스템 |
| `srvadm` | pickle (서버관리) |

프로젝트는 DB에 저장되며 추후 추가 가능하다. 각 프로젝트는 **로고 이미지**를 가진다
(하단 디스크 메뉴에 사용).

## 3. 시스템 구성

React 앱 **하나**를 경로로 나누고, 스프링부트 서버 **하나**를 공유한다.

```
                    ┌──────────────────────────┐
   실사용자  ─────▶ │  /  · /write · /my       │  사용자용 화면
                    ├──────────────────────────┤
   개발자    ─────▶ │  /admin/...              │  관리용 화면
   실장님    ─────▶ │  (로그인 권한으로 차단)   │
                    └────────────┬─────────────┘
                                 │  /api/**
                    ┌────────────▼─────────────┐
                    │  Spring Boot + PostgreSQL │
                    └──────────────────────────┘
```

- 프론트: React (Vite) 단일 프로젝트, 라우팅으로 사용자용/관리용 분리
- 백엔드: Spring Boot 3.5.6 / JDK 21 / JPA / Spring Security / PostgreSQL (로컬은 H2)
- `/admin/**` 은 로그인 + 권한 검사를 통과해야 진입. **화면 숨김이 아니라 API 단에서 막는다.**

## 4. 역할과 권한

권한 계층은 **2단계**다. 이 서비스를 가장 많이 쓰는 사람이 개발자이므로,
**개발자가 실질적 최고 권한**을 가진다. 실장님은 열람과 '픽'을 담당한다.

| 역할 | 코드 | 누구 | 할 수 있는 일 |
|---|---|---|---|
| 개발자 | `DEVELOPER` | 개발팀 5명 | 전체 프로젝트 열람·수정, 상태 변경, 답변 작성, 카테고리·중요도 수정, **계정 승인 및 역할 부여** |
| 실장 | `DIRECTOR` | 실장님, 선생님 | 전체 열람, 대시보드 조회, **실장님 픽** |
| 일반 사용자 | `USER` | 구글 로그인 사용자 | 피드백 작성, 내 문의 조회 |
| 비회원 | (계정 없음) | 게스트 | 피드백 작성만 (1회성) |

- **모든 개발자는 완전히 동일한 권한을 가진다.** 담당 프로젝트 구분 없이 서로 백업할 수 있다.
- 계정 승인도 개발자 누구나 할 수 있다. (아무나 개발자로 승인해 버릴 위험은 팀 내 신뢰로 감수)
- 실장 역할은 상태 변경·답변을 할 수 없다. 실수로 개발 상태를 바꾸는 일을 막기 위함이다.

### 계정 승인 흐름

```
구글 로그인으로 /admin 최초 접근
        ↓
users 테이블에 status = PENDING 으로 생성
        ↓
"승인 대기 중입니다" 안내 화면 (기능 접근 불가)
        ↓
기존 개발자가 관리 화면에서 역할(DEVELOPER / DIRECTOR) 지정 후 승인
        ↓
status = ACTIVE, 정상 이용
```

## 5. 피드백 도메인 규칙

### 5-1. 유형 (카테고리)

| 유형 | 코드 | 설명 |
|---|---|---|
| 오류 신고 | `BUG` | 서비스 이용 중 발생한 오류나 문제 |
| 기능 제안 | `FEATURE` | 기존 서비스에 추가되었으면 하는 기능 |
| 기타 의견 | `ETC` | 위 둘에 포함되지 않는 의견 |

> 초기 논의에서 "문제 신고"라는 이름도 나왔으나, README에 이미 쓰인 **"오류 신고"로 통일**한다.

카테고리는 사용자가 작성 시 고르고, 개발자가 나중에 **수정할 수 있다**
(사용자가 기능 제안을 오류로 잘못 분류하는 경우가 잦기 때문).

### 5-2. 진행 상태

상태는 **4단계**이고, 칸반 보드는 그중 3개를 열로 쓴다.

| 상태 | 코드 | 칸반 위치 | 배지 색 | 설명 |
|---|---|---|---|---|
| 접수 | `RECEIVED` | 1열 (진행 전) | 파랑 | 사용자가 제출한 상태 |
| 처리 중 | `IN_PROGRESS` | 2열 (진행 중) | 주황 | 수정·조치를 진행 중 |
| 처리 완료 | `DONE` | 3열 (완료) | 초록 | 조치가 완료됨 |
| 반영 불가 | `REJECTED` | 보드 밖 (별도 목록) | 회색 | 현재 반영하기 어려움 |

- `REJECTED`는 칸반 열을 차지하지 않고, 보드 상단의 "반영 불가 N건" 토글로 펼쳐 본다.
  보드는 **지금 할 일**만 보여야 하기 때문이다.
- 상태 변경은 개발자만 가능하며, 카드를 드래그하거나 상세에서 바꾼다.

### 5-3. 중요도

| 값 | 코드 |
|---|---|
| 높음 | `HIGH` |
| 보통 | `NORMAL` (기본값) |
| 낮음 | `LOW` |

중요도는 **두 개의 값**으로 관리한다.

- `reported_priority` — 사용자가 작성할 때 고른 체감 긴급도. 참고용이며 정렬에 쓰지 않는다.
- `priority` — 개발자가 확정한 최종 중요도. **정렬은 이 값을 쓴다.** 최초에는 `reported_priority` 값으로 시작한다.

상세 화면에는 "사용자 체감: 높음 / 최종: 보통"처럼 둘 다 보여 준다.

### 5-4. 실장님 픽

실장님이 "이건 먼저 처리해 주세요"라고 말하는 버튼.

- 토글이다. 다시 누르면 해제된다. 개수 제한은 없다.
- 픽하면 **최종 중요도가 자동으로 `HIGH`로 올라간다.**
- 픽하면 **담당 개발자에게 알림 메일이 발송된다.**
- 픽된 피드백은 **어떤 정렬을 걸어도 목록 맨 위에 고정**되고 ★ 배지가 붙는다.
- 개발자가 픽을 해제할 수는 없다. (실장님과 개발자 본인만 해제)
- 픽 이후 개발자가 중요도를 수동으로 낮추는 것은 가능하다. 픽 배지와 상단 고정은 유지된다.

### 5-5. 정렬과 필터

정렬은 **항상 "실장님 픽 먼저"가 적용된 뒤**, 선택한 기준으로 정렬된다.

| 정렬 | 규칙 |
|---|---|
| 중요도순 | 픽 → 높음 → 보통 → 낮음, 같으면 최신순 |
| 최신순 | 픽 → 작성일 내림차순 |
| 오래된순 | 픽 → 작성일 오름차순 |

필터: 사이트별 / 진행 상태별 / 유형별 / 기간별 / 회원·비회원.

## 6. 사용자용 사이트

### 6-1. 전체 흐름

```
                     ┌─────────────────┐
                     │   로그인 화면    │
                     └────────┬────────┘
              ┌───────────────┴───────────────┐
       [구글 로그인]                     [비회원으로 계속]
              │                               │
              ▼                               ▼
      ┌───────────────┐            ┌────────────────────┐
      │  홈 (내 문의)  │            │  경고 팝업          │
      │  · 이전 질문   │            │  "비회원은 답변을   │
      │    목록        │            │   받을 수 없습니다" │
      │  · 새 질문 적기│            │  [로그인] [계속]    │
      └───────┬───────┘            └─────┬──────────┬───┘
              │                          │          │
              │              [로그인]────┘          │ [계속]
              │                                     │
              └──────────────┬──────────────────────┘
                             ▼
                   ┌───────────────────┐
                   │  피드백 작성 화면  │
                   └─────────┬─────────┘
                             ▼
                   ┌───────────────────┐
                   │ "질문이 접수되었습 │
                   │  니다" 팝업        │
                   └───────────────────┘
```

### 6-2. 사이트 지정 방식

피드백이 **어느 사이트에 대한 것인지**는 진입 링크로 정해진다.

- 각 시스템에 `https://피드백주소/?site=aipms` 형태의 링크를 심는다.
- 이렇게 들어오면 사이트가 **자동 지정되고 사용자는 바꿀 수 없다.** (오분류 방지)
- 예외: 회원이 홈에서 `새 질문 적기`를 누른 경우에는 사이트 정보가 없으므로,
  **그때만 사이트 선택 드롭다운이 나타난다.**

### 6-3. 화면 명세

#### (1) 로그인 화면 `/`

- 서비스 이름과 한 줄 설명
- `구글로 로그인` 버튼
- `비회원으로 계속` 버튼

비회원 버튼을 누르면 모달이 뜬다.

```
┌──────────────────────────────────────┐
│  비회원으로 계속하시겠습니까?         │
│                                      │
│  비회원은 답변을 받을 수 없고,        │
│  작성한 내용과 진행 상태를 다시       │
│  확인할 수 없습니다.                  │
│                                      │
│        [ 로그인 ]   [ 계속 ]          │
└──────────────────────────────────────┘
```

- `로그인` → 구글 로그인으로 이동
- `계속` → 홈을 건너뛰고 **바로 작성 화면으로 이동**

#### (2) 홈 `/home` (회원 전용)

- 상단: 사용자 이름, 로그아웃
- `새 질문 적기` 버튼 (강조)
- 내가 보낸 질문 목록 — 최신순
  - 각 항목: 사이트 배지 · 제목 · 유형 · 상태 배지 · 작성일 · 답변 여부(●)
  - 클릭하면 상세로 이동
- 목록이 비어 있으면 "아직 보낸 질문이 없습니다" 안내

#### (3) 피드백 작성 `/write`

| 항목 | 형태 | 필수 | 비고 |
|---|---|---|---|
| 사이트 | 고정 표시 (링크 진입 시) / 드롭다운 (홈 진입 시) | O | 링크 진입 시 수정 불가 |
| 유형 | 라디오 3개 (오류 신고 / 기능 제안 / 기타 의견) | O | 기본값 없음 |
| 긴급도 | 라디오 3개 (높음 / 보통 / 낮음) | O | 기본값 보통 |
| 제목 | 한 줄 입력, 100자 | O | |
| 내용 | 여러 줄 입력, 2000자 | O | 최소 10자 |

`작성` 버튼을 누르면 `질문이 접수되었습니다` 팝업이 뜬다.

- 회원: 확인 → 홈으로 이동
- 비회원: 확인 → 로그인 화면으로 이동 (세션 종료)

#### (4) 내 문의 상세 `/my/{id}` (회원 전용)

- 내가 쓴 제목·내용·유형·작성일
- 현재 상태 배지 (접수 / 처리 중 / 처리 완료 / 반영 불가)
- 개발자 답변 (없으면 "아직 답변이 등록되지 않았습니다")

사용자는 자기 글을 **수정·삭제할 수 없다.** (처리 중인 항목이 사라지면 개발자가 혼란)

## 7. 관리용 사이트

### 7-1. 화면 구조

```
┌─────────────────────────────────────────────────────────────┐
│  [로고]  통합 피드백 게시판            문진혁(개발자) ▾      │  ← 공통 헤더
├─────────────────────────────────────────────────────────────┤
│ ╭──────────╮╭────────╮                                      │
│ │ 개발 보드 ││  답변  │                                      │  ← 상단 탭
│ ╰──────────╯╰────────╯                          (브라우저 탭 모양)
├─────────────────────────────────────────────────────────────┤
│                                                             │
│                     현재 탭의 내용                           │
│              (칸반 보드 또는 답변 대기열)                     │
│                                                             │
│                                                             │
├─────────────────────────────────────────────────────────────┤
│                        ⬤ CODEPLACE                          │
│                   ○              ○                          │  ← 하단 회전 디스크
│               ○                      ○                      │     (프로젝트 이동)
│              ╲______화면 아래로 잘림______╱                  │
└─────────────────────────────────────────────────────────────┘
```

- **하단 = 프로젝트 이동.** 원형 디스크(LP판/룰렛 형태)에 프로젝트 로고를 호(arc)를 따라 배치.
  좌우로 드래그하거나 로고를 클릭하면 원이 회전하고, 정상단에 온 프로젝트가 선택된다.
  디스크의 아래쪽 절반은 화면 밖으로 잘려 보이지 않는다.
- **상단 = 프로젝트 안에서의 메뉴 이동.** 브라우저 탭처럼 생긴 탭 2개.
- 디스크의 정상단 슬롯 중 하나로 **홈(전체 대시보드)** 진입점을 함께 둔다.

### 7-2. 홈 — 전체 현황 대시보드

실장님이 사실상 이 화면만 쓴다. **조회 전용의 단순한 페이지**이며 여기서 작업을 하지는 않는다.

레이아웃 (첨부 대시보드 이미지 참고):

```
┌──────────┬──────────┬──────────┬──────────┬──────────┐
│ 전체     │ 접수     │ 처리 중  │ 처리 완료│ 반영 불가 │   ← 상단 지표 카드
│ 1,204건  │ 88건     │ 32건     │ 1,050건  │ 34건      │
└──────────┴──────────┴──────────┴──────────┴──────────┘
┌───────────────────────────┬─────────────────────────────┐
│ 프로젝트별 현황 (막대)     │ 기간별 피드백 추이 (선)      │
│ 5개 프로젝트 × 상태 누적   │ 최근 30일                    │
├───────────────────────────┼─────────────────────────────┤
│ 유형별 비율 (도넛)         │ 평균 처리 소요 시간          │
│ 오류/기능/기타             │ 전체 · 프로젝트별 상위 3개   │
└───────────────────────────┴─────────────────────────────┘
┌─────────────────────────────────────────────────────────┐
│ ★ 실장님 픽 목록 · 최근 접수 10건                        │
└─────────────────────────────────────────────────────────┘
```

지표 정의:

| 지표 | 계산 |
|---|---|
| 상태별 건수 | 상태별 `count` |
| 프로젝트별 현황 | 프로젝트 × 상태 교차 집계 |
| 유형별 비율 | 유형별 `count` / 전체 |
| 기간별 추이 | 일자별 접수 건수 (기본 30일) |
| 평균 처리 소요 시간 | `closed_at - created_at` 평균 (완료·반영 불가만) |
| 사용자 수 | 피드백을 1건 이상 남긴 고유 사용자 수 (비회원은 별도 집계) |

### 7-3. 프로젝트 상세 — 탭 1 : 개발 보드

개발자가 실제로 일하는 화면. 칸반 3열.

```
정렬 [중요도순 ▾]  유형 [전체 ▾]  기간 [전체 ▾]      반영 불가 3건 ▸

┌── 진행 전 (12) ──┬── 진행 중 (4) ───┬── 완료 (58) ────┐
│ ★[높음] 로그인   │  [보통] 목록 정렬 │  [낮음] 오타     │
│    실패          │    깨짐           │    수정          │
│  오류신고 · 3일전│  오류신고 · 1일전 │  기타 · 6일전    │
├──────────────────┼──────────────────┼─────────────────┤
│  [보통] 다크모드 │                  │                 │
│  기능제안 · 5일전│                  │                 │
└──────────────────┴──────────────────┴─────────────────┘
```

- 카드에 표시: 픽 ★ · 중요도 배지 · 제목 · 유형 · 경과일 · 답변 여부
- 카드를 드래그해 열 사이로 옮기면 상태가 바뀐다. (클릭 → 상세에서도 변경 가능)
- 카드 클릭 시 우측 패널이 열려 전체 내용, 카테고리 수정, 중요도 수정, 답변 바로가기 제공
- 정렬은 열 안에서 적용된다.

### 7-4. 프로젝트 상세 — 탭 2 : 답변

사용자에게 회신하는 화면. 보드와 달리 **목록형**이다.

```
[ 답변 필요 8 ] [ 답변 완료 41 ] [ 전체 ]        정렬 [오래된순 ▾]

┌───────────────────────────────────────────────────────┐
│ ★ [높음] 로그인이 안 됩니다            오류신고 · 3일전 │
│   홍길동(회원) · 상태: 처리 중                          │
│   "크롬에서 로그인 버튼을 누르면 아무 반응이..."         │
│                                        [ 답변 쓰기 ]   │
└───────────────────────────────────────────────────────┘
```

- 기본 필터는 `답변 필요`(회원이 쓴 글 중 답변 없는 것), 기본 정렬은 `오래된순`
- **비회원 글은 답변 대상이 아니므로 "비회원" 배지와 함께 흐리게 표시**되고 답변 버튼이 없다
- 답변은 **1건만** 달 수 있고, 등록 후 수정할 수 있다. 수정하면 사용자에게 다시 메일이 가지 않는다
- 답변 등록 시 상태를 함께 바꿀 수 있는 체크박스 제공 ("처리 완료로 변경")

### 7-5. 계정 관리 (개발자 전용)

- 승인 대기 목록: 이메일, 이름, 가입일 → 역할 선택 후 `승인` / `거절`
- 기존 계정 목록: 역할 변경, 비활성화
- 접근 경로: 헤더 우측 사용자 메뉴 → `계정 관리`

## 8. 알림

| 시점 | 받는 사람 | 방식 |
|---|---|---|
| 개발자가 답변 등록 | 피드백 작성자(회원) | 이메일 + 사이트 내 표시 |
| 실장님이 픽 | 개발자 전원 | 이메일 |

- 비회원은 이메일을 수집하지 않으므로 어떤 알림도 발송하지 않는다.
- 답변 **수정** 시에는 메일을 보내지 않는다. (오탈자 수정마다 메일이 가는 것을 방지)
- 발송 실패는 로그로 남기고 사용자 요청을 실패시키지 않는다. (알림은 부가 기능)
- 메일 본문에는 피드백 제목과 답변 링크만 담고, 내용 전문은 넣지 않는다.

```
projects           users                     feedbacks                 answers
─────────          ─────────                 ────────────              ─────────
id                 id                        id                        id
code               email                     project_id      ─┐        feedback_id ─┐
name               name                      author_id       ─┼─┐      author_id    │

sort_order         status                    content          │ │      updated_at   │
                   created_at                category         │ │                   │
                                             status           │ │                   │
                                             reported_priority│ │                   │
                                             priority         │ │                   │
                                             director_picked  │ │                   │
                                             created_at       │ │                   │
                                             first_answered_at│ │                   │
                                             closed_at        │ │                   │
                                                              │ │                   │
              projects.id ─────────────────────────────────────┘ │                   │
              users.id  ──────────────────────────────────────────┘                  │
              feedbacks.id ──────────────────────────────────────────────────────────┘
```

| 컬럼 | 비고 |
|---|---|
| `users.role` | `USER` / `DEVELOPER` / `DIRECTOR` |
| `users.status` | `PENDING` / `ACTIVE` / `DISABLED` |
| `feedbacks.author_id` | 비회원이면 `NULL` |
| `feedbacks.author_type` | `MEMBER` / `GUEST` |
| `feedbacks.reported_priority` | 사용자가 고른 긴급도 (참고용) |
| `feedbacks.priority` | 최종 중요도 (정렬 기준) |
| `feedbacks.director_picked` | 실장님 픽 여부 |
| `feedbacks.first_answered_at` | 답변 소요 시간 통계용 |
| `feedbacks.closed_at` | `DONE` 또는 `REJECTED`가 된 시각. 처리 시간 통계용 |

비회원 피드백도 모두 저장한다. 통계와 중복 신고 확인에 필요하기 때문이다.

## 10. API 초안

### 공개

| 메서드 | 경로 | 설명 |
|---|---|---|
| `GET` | `/api/projects` | 프로젝트 목록 (로고 포함) |
| `POST` | `/api/feedbacks` | 피드백 등록 (비회원 허용) |

### 회원

| 메서드 | 경로 | 설명 |
|---|---|---|
| `GET` | `/api/me` | 내 정보 |
| `GET` | `/api/me/feedbacks` | 내 문의 목록 |
| `GET` | `/api/me/feedbacks/{id}` | 내 문의 상세 (답변 포함) |

### 관리 (`DEVELOPER` / `DIRECTOR`)

| 메서드 | 경로 | 권한 | 설명 |
|---|---|---|---|
| `GET` | `/api/admin/dashboard` | 둘 다 | 전체 대시보드 지표 |
| `GET` | `/api/admin/feedbacks` | 둘 다 | 목록. `project`,`status`,`category`,`sort`,`from`,`to` |
| `GET` | `/api/admin/feedbacks/{id}` | 둘 다 | 상세 |
| `PATCH` | `/api/admin/feedbacks/{id}` | 개발자 | 상태·유형·중요도 수정 |
| `PUT` | `/api/admin/feedbacks/{id}/answer` | 개발자 | 답변 등록·수정 |
| `POST` | `/api/admin/feedbacks/{id}/pick` | 실장 | 픽 토글 |
| `GET` | `/api/admin/users` | 개발자 | 계정 목록 |
| `PATCH` | `/api/admin/users/{id}` | 개발자 | 승인·역할 변경 |

권한은 화면이 아니라 **API에서 검사**한다. `DIRECTOR`가 `PATCH /feedbacks`를 호출하면 403.

## 11. 인증

- 사용자용·관리용 모두 **구글 로그인** 하나만 쓴다. (자체 비밀번호를 만들지 않음)
- 관리 화면은 구글 로그인 후 **`users.status = ACTIVE` 이고 역할이 `DEVELOPER` 또는 `DIRECTOR`** 여야 진입 가능
- 최초 개발자 1명은 DB에 직접 넣어 부트스트랩한다. 이후는 화면에서 승인
- 비회원은 계정을 만들지 않는다. 작성 후 세션이 끝나면 추적할 수단이 없다 (의도된 동작)

## 14. 개발 순서

| 단계 | 내용 | 산출물 |
|---|---|---|
| 1 | 도메인·DB 스키마, 프로젝트 시드 데이터 | 엔티티, 마이그레이션 |
| 2 | 피드백 등록 API + 사용자용 작성 화면 (비회원 경로) | 비회원이 신고 가능 |
| 3 | 구글 로그인, 사용자 홈·내 문의 상세 | 회원 경로 완성 |
| 4 | 관리 목록 API, 권한 검사, 칸반 보드 | 개발자가 상태 관리 가능 |
| 5 | 답변 탭, 답변 등록·수정 | 사용자에게 회신 가능 |
| 6 | 대시보드 지표 API + 홈 화면 | 실장님 화면 완성 |
| 7 | 하단 회전 디스크, 상단 탭 등 UI 마감 | 디자인 완성 |
| 8 | 실장님 픽, 이메일 알림, 계정 관리 | 부가 기능 |
| 9 | 배포, 각 사이트에 링크 삽입 | 오픈 |

2~3단계와 4~5단계는 프론트/백을 나눠 병렬로 진행할 수 있다.
